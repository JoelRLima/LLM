# Auditoria de botões — WebView2

Foram verificados os **18 botões estáticos** do HTML e o botão de oferta de relatório criado por settlement. Antes deste ajuste, cinco botões estavam habilitados sem handler: Chat, Atualizar artefatos, menu do perfil, Atalhos e Mais opções do relatório.

Após o ajuste, dez botões têm ação associada e oito permanecem desabilitados com explicação. **Nenhum botão habilitado está sem ação.** Os recursos indisponíveis não foram implementados nesta rodada.

| Botão | Ação ou estado |
|---|---|
| Recolher navegação | Alterna a largura da navegação |
| Chat | Foca o campo de mensagem da conversa atual — associado nesta rodada |
| Arquivos | Desabilitado: painel não implementado |
| Tarefas | Desabilitado: painel não implementado |
| Ferramentas | Desabilitado: painel não implementado |
| Atualizar artefatos | Desabilitado nesta rodada: atualização manual não implementada; relatórios chegam pelo settlement |
| Relatórios | Abre o relatório mais recente; habilitado quando há referência disponível |
| Menu do perfil | Desabilitado nesta rodada: menu não implementado |
| Modelo real não conectado | Indicador desabilitado: fixture offline, sem conexão/verificação de modelo real |
| Alternar tema | Alterna tema claro/escuro |
| Atalhos | Mostra ajuda: Ctrl+Enter envia; Enter cria nova linha — associado nesta rodada |
| Analise notes.txt | Preenche a sugestão e submete a solicitação |
| Anexar arquivo | Desabilitado: anexos não implementados; motivo agora explícito |
| Parar | Solicita cancelamento da execução ativa; aguarda settlement |
| Enviar | Submete o texto, com coordenação de identidade/geração |
| Fechar painel | Fecha o painel e invalida leituras pendentes |
| Mais opções do relatório | Desabilitado nesta rodada: menu não implementado |
| Copiar texto | Copia a leitura válida; desabilitado durante leitura/falha/fechamento |
| Abrir relatório (dinâmico) | Abre a referência específica da oferta na conversa |

O anúncio de `⌘1` no botão Chat foi removido: não havia implementação desse atalho. A dica do compositor foi alinhada ao comportamento real, Ctrl+Enter para enviar. Os ícones de funções desabilitadas receberam nomes/explicações e estilo de indisponibilidade.

## Verificação

`test_webview_buttons.mjs` enumera cada `<button>`, exige identidade estável, verifica a associação do handler ou estado desabilitado com explicação e executa as **dez ações** em DOM mínimo. Também executa o botão dinâmico de relatório e verifica os efeitos: foco, tema, navegação, ajuda, submissão, cancelamento, leitura, cópia e fechamento. A cópia usa clipboard simulado; não altera o clipboard do usuário.

Passaram a auditoria dos botões, os **17 cenários de submissão/disponibilidade**, os **12 cenários anteriores de frontend** e os **5 testes de bridge/fixture**. Resultados novos em `evidence/buttons-20261022/results.json`. A execução JavaScript usou o runtime Node de `node_repl`.

```powershell
node prototypes/workbench-comparison/test_webview_buttons.mjs
node prototypes/workbench-comparison/test_webview_submission.mjs
node prototypes/workbench-comparison/test_webview_ui.mjs
.venv/Scripts/python.exe prototypes/workbench-comparison/test_webview_bridge.py
```

Não houve inspeção visual humana nesta rodada. Reabrir o protótipo para carregar as mudanças. Tk, application, contratos e evidências anteriores foram preservados; não houve carregamento de modelo, commit, merge ou publicação.
